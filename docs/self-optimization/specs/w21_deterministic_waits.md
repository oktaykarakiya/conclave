# W21 Deterministic waits: the test suite passes on a loaded host

Make the test suite pass on a loaded machine: no test may depend on how fast the host is.

Found live on 2026-11-20 while another project compiled on the same host (load average about 40 on this machine): `tests/unit/test_planning_orchestrator.py::test_approve_session_on_active_cancels_loop_before_create` failed on every run, on master too (it passed in every earlier run). It starts a planning session whose first planner turn runs in the background, sleeps a fixed `asyncio.sleep(0.1)`, then asserts the turn already created its two task nodes (`assert len(nodes_before) == 2`, got 0). The full suite took 24 minutes instead of 6. A test like this fails the green gate on a busy host and costs the task an attempt.

REQUIRED
1. Find every test that waits a fixed time for something to happen in the background (a task, a subprocess, a worker tick, an event, a file) and then asserts it happened. There are 31 `await asyncio.sleep(<fraction>)` calls under `tests/` and 13 `time.sleep(` calls; read each in context. The same applies to waits that already poll or wait but give up too soon for a loaded host: 11 `asyncio.wait_for(..., timeout=<5 s)` that expect the result to arrive (`tests/unit/test_events.py`, `tests/integration/test_mcp.py`), and bounded polls such as `for _ in range(20): await asyncio.sleep(0.01)` (`tests/integration/test_task_merge.py`, `tests/integration/test_quota_wait.py`, `tests/unit/test_quota_gate.py`); give each a deadline of 10 seconds or more. Replace each such wait with a poll for the condition itself, with a generous deadline (10 seconds or more) that fails with a message naming what never happened. Put the helper in one shared place the tests import (for example `tests/integration/waits.py`, or `conftest.py`), so every test polls the same way.
   - Keep a sleep that only yields control on purpose (letting another coroutine reach an await, ordering two writers in a race test), or that asserts something does NOT happen within a window. Say why in a short comment where that is not obvious.
2. Wall-clock assertions (`elapsed < N`, `time.monotonic() - started < N`) must not fail on a slow host while still catching the defect they guard. Where a test guards against a hang or a full wait (a 5-second sleep that must be killed), keep the bound but make sure it has at least 2× headroom over the real path on a loaded host. Where a test guards complexity (`tests/unit/test_test_integrity_scan.py`: a quadratic scan), compare two sizes on the same host (for example 4× the input must take less than 8× the time; a linear scan takes about 4×, a quadratic one 16×) instead of an absolute time.
3. Prove it without slowing anything else on the host (it runs other work): pin pytest and two busy processes (`python -c "while True: pass"`) to one CPU core with `taskset -c <core>`, so they contend only with each other; kill the busy processes afterwards. Under this load, run the full suite once (it can take 30 minutes or more: give the command a long enough timeout) and every changed test file three times; all must pass. Report the suite's normal wall time and its time under this load.

CONSTRAINTS
- Change only `tests/` (and AGENTS.md's test count, if it changes); no product code changes.
- Never weaken what a test checks: the condition asserted after the wait stays the same; only how long the test is willing to wait changes. Never skip or delete a test; never add a retry-on-failure plugin.
- Tests stay deterministic and hermetic (no network, no real LLM, never the live daemon).
- Quality gate (must stay green): `ruff check src tests && mypy && pytest -q` and `cd frontend && npx tsc --noEmit && npm run build`.
